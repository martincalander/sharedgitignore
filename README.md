# sharedgitignore

`sharedgitignore` keeps a generated block at the top of a repository's
`.gitignore`. Anything below that block belongs to the repository and is left
alone.

The rules are committed in `.gitignore`, not linked or included from somewhere
else. Clones do not need `sharedgitignore` installed; the local registry only
maps profiles back to their source templates.

## Install

Requires Node.js 24+ and Git. Install the pinned release from GitHub:

```bash
npm install -g github:martincalander/sharedgitignore#v2.0.0
sharedgitignore --version
```

This package is not published to npm and remains `UNLICENSED`.

## Quick start

Register a template, then initialize a repository with it:

```bash
sharedgitignore profile add unity /path/to/unity.gitignore.shared
sharedgitignore init --profile unity --cwd /path/to/repo
```

The result:

```gitignore
### BEGIN SHAREDGITIGNORE profile=unity version=1 ###
# DO NOT EDIT. Generated by sharedgitignore.
# Run: sharedgitignore sync

...rules from the unity template...
### END SHAREDGITIGNORE - PROJECT RULES BELOW ###

...rules owned by this repository...
```

After changing the template, update the repository and commit the result:

```bash
sharedgitignore sync --cwd /path/to/repo
```

In CI, use `check` to fail on a stale block:

```bash
sharedgitignore check --cwd /path/to/repo
```

## Profiles

Profiles are stored in `~/.sharedgitignore/registry.json`. Set
`SHAREDGITIGNORE_HOME` to keep the registry somewhere else.

```bash
sharedgitignore profile add <id> <template-path>
sharedgitignore profile remove <id>
sharedgitignore profile list
sharedgitignore profile status
```

The registry stores the resolved absolute path to each template. Profile IDs
must match `[a-z0-9][a-z0-9._-]*`; they are not trimmed.

A template must be a readable UTF-8 file with no BOM or NUL byte. It cannot be
the target `.gitignore`, and it cannot contain lines beginning with the managed
block markers.

Registry files use mode `0600`, and profile changes are serialized with a lock.
If a process dies while holding it, the next write reports the lock path and
owner. Confirm no profile command is running, then delete the stale lock.

## Repository commands

Preview a change with `--dry-run`:

```bash
sharedgitignore init --profile unity --cwd /path/to/repo --dry-run
sharedgitignore sync --cwd /path/to/repo --dry-run
```

Inspect a repository without changing it:

```bash
sharedgitignore detect --cwd /path/to/repo
sharedgitignore detect --cwd /path/to/repo --json
```

File handling:

- Everything below the end marker is preserved byte for byte, including
  non-UTF-8 data.
- LF and CRLF are treated as equal inside the generated block. Checkout filters
  will not make a current file look stale.
- `init` rejects an unmanaged `.gitignore` with a UTF-8 BOM. Prepending a block
  would move the BOM and change the first Git rule, so remove it first.
- Malformed or duplicate markers are errors.
- Symlinks and non-file destinations are rejected.
- Before replacing a file, the tool rechecks the repository, `.gitignore`, and
  template. The replacement uses a temporary sibling and atomic rename while
  keeping the existing file mode.

## Multiple repositories

`check-all` and `sync-all` scan a directory for managed repositories:

```bash
sharedgitignore check-all --root /path/to/repos
sharedgitignore sync-all --root /path/to/repos --dry-run
sharedgitignore sync-all --root /path/to/repos
```

Batch commands finish discovery and preflight before writing, then recheck each
repository immediately before updating it.

Nested repositories are included by default. The scanner skips `.git`,
`node_modules`, `Library`, `Temp`, `Obj`, `Build`, and `Builds`. Pass
`--no-recursive` to stop below the first repository found in each tree.

Unmanaged repositories are skipped. Scan errors, bad templates, malformed
blocks, and stale checks exit nonzero. A write failure stops the run without
rolling back earlier updates; the summary reports how many completed.

## Command reference

```text
sharedgitignore --version
sharedgitignore --help

sharedgitignore profile add <id> <path>
sharedgitignore profile remove <id>
sharedgitignore profile list
sharedgitignore profile status

sharedgitignore detect [--cwd path] [--json]
sharedgitignore init --profile <id> [--cwd path] [--dry-run]
sharedgitignore sync [--cwd path] [--dry-run]
sharedgitignore check [--cwd path]
sharedgitignore sync-all --root <path> [--no-recursive] [--dry-run]
sharedgitignore check-all --root <path> [--no-recursive]

sharedgitignore completion zsh
sharedgitignore completion install [--dir path]
```

Options go after their command (and subcommand, if there is one). Duplicate
options and missing values are rejected. Use `--` before a positional value
that starts with `--`:

```bash
sharedgitignore profile add base -- --template-file
```

## Zsh completion

```bash
sharedgitignore completion install
```

The default destination is `~/.zsh/completions/_sharedgitignore`. Pass `--dir`
or set `SHAREDGITIGNORE_ZSH_COMPLETION_DIR` to use another directory. Make sure
that directory is in `fpath` before `compinit` runs:

```zsh
fpath=("$HOME/.zsh/completions" $fpath)
autoload -Uz compinit
compinit
```

The installer only writes the completion file; update `.zshrc` yourself.

## Upgrading from v1

V2 still uses registry version `1` and managed-block version `1`, so there is no
format migration. It does validate old data more strictly. After upgrading,
check the registered templates and repositories:

```bash
sharedgitignore profile status
sharedgitignore check-all --root /path/to/repos
```
